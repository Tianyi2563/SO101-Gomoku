# 项目整体状态与推进清单

更新：2026-11-17。依据用户最初规划、本地业务代码和最近测试记录整理；本次未重新连接硬件或重跑测试。

## 当前结论

已形成可运行的软件对弈闭环：规则、AI、IK接口、基础视觉、取放流程及回合调度均有实现。实际系统仍缺实拍验证、实物标定、连续运动和抓放验证，以及真实相机/机械臂运行入口。不能描述为“整个项目代码已完成，只差插上机械臂”。

当前确认：单臂；机器人黑棋先手，人类白棋；自由五子棋（长连有效、无禁手）；9×9方格=10×10交点，索引0..9；实际棋盘采用Alpha-Beta。用户提供约21mm格距，对应交点跨度约189mm；打印后X/Y实际间距仍待测。

最近完整测试记录：56项通过（data/vision-tests.log）。属于软件单元/集成及合成图测试，不是56项真机验收。

## 按优先级推进

### P0 固定实物定义与输入

- [ ] 测量实际交点间距、棋子直径/高度、夹爪接触点；记录单臂/相机/棋盘/供料位置。
- [ ] 固定俯拍相机与曝光，保存同机位空盘、黑白棋、边角、相邻/密集棋、手/机械臂遮挡照片。
- [ ] 确认本机串口、标定文件、关节顺序/符号/零位、实际关节限位和工具点；不要直接把URDF限位当电机实测值。

交付：真实配置表、图片样本包；不需要先开发网页。

### P1 实拍识别与标定工具（可并行）

- [ ] 用真实照片设置最外侧四交点、更新空盘参考并调整分类阈值。
- [ ] 评估黑/白/空混淆、unknown覆盖率及错误高置信输出，不以大量unknown换取表面准确率；加入实拍回归。
- [ ] 补齐示教点采集、棋盘到基座拟合、保存/加载、标定版本以及独立验证点误差报告。
- [ ] 固定机位先用手动角点完成闭环；移动或需自动重定位时再实现ArUco。畸变是否需校正以实拍误差决定。

交付：稳定的真实get_board_state()、本机标定文件和独立点误差。

### P2 真机单点与单次取放

- [ ] 在无抓取条件下验证四角、边中附近、中央附近的代表交点及供料点。10×10交点没有唯一中心交点，选定明确row/col记录。
- [ ] 先验证安全高度目标及末端方向，再验证完整路径，不以终点IK有解代替全路径可行。
- [ ] 补充受限速度/平滑运动、超时反馈、真实抓取确认、松爪/撤退观察姿态。
- [ ] 完成固定供料到指定交点的一次取放，失败暂停并人工检查，不自动重试。

交付：place_piece(row,col)实体原型和落点误差/失败原因记录。

### P3 第一轮实体闭环

- [ ] 组装真实camera→BoardObserver→GameController→Alpha-Beta→TaskExecutor→实测planner→PickAndPlace。
- [ ] 空盘确认后机器人黑先；新观测验证黑棋存在，再允许人类白棋。
- [ ] 人类白棋稳定确认后机器人再次决策/放黑棋；验证后再提交。
- [ ] 注入遮挡、缺棋、执行失败、错位落子，确认暂停与对账恢复，不多走一步。

交付：机器人黑→人类白→机器人黑的可复现实物回合。

### P4 可靠性与演示

- [ ] 同一落点重复20次，多代表交点统计定位/取放成功率。
- [ ] 周围八点占满、中央为空的密集放置实验。
- [ ] 连续至少5次人机交替回合；明确固定供料支持的步数和补棋方式。
- [ ] 保存原图、观测、棋局/标定版本、任务和结果，补完整回放/重启恢复。
- [ ] 最后接JARVIS界面，展示真实棋局、unknown、暂停原因及恢复操作。
