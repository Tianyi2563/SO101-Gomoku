## 1. 正运动学（FK）

### 1.1 URDF 给了什么

`assets/so101_new_calib.urdf` 里每个关节描述了：父/子连杆、原点变换
（平移 `xyz` + 旋转 `rpy`，rpy 是固定轴 XYZ 即 `R = Rz·Ry·Rx`）、旋转轴、限位。

解析后得到 5 个可动关节的链：

| 关节 | 行程 | 说明 |
|------|------|------|
| shoulder_pan | ±110° | 底座旋转 |
| shoulder_lift | ±100° | 肩部俯仰 |
| elbow_flex | ±96.83° | 肘 |
| wrist_flex | ±95° | 腕俯仰 |
| wrist_roll | ±160° | 腕自转 |

### 1.2 齐次变换连乘

```
T_tip = ∏ ( T_origin(i) · R_axis(i, q_i) )
```

`R_axis` 用 Rodrigues 公式算。末端位置就是 `T_tip[:3, 3]`。
`tools/inspect_urdf.py` 里做了自检：零位时末端在 `(0.391, 0.000, 0.226)` m。

### 1.3 几何雅可比

对旋转关节，第 i 列：

```
Jv_i = axis_i^world × (p_tip - p_i^world)
Jw_i = axis_i^world
```

`axis^world` 由该关节坐标系的方向矩阵作用到局部轴上得到
（绕自身轴旋转不改变轴的方向，所以"旋转前"的坐标系就够了）。

**自检**：解析雅可比与中心差分数值雅可比的最大偏差 1.56e-11 —— 实现无误。

## 2. 关节角单位：URDF 弧度 ↔ lerobot 动作值

lerobot 下发的动作值是无量纲百分数（臂关节 −100…+100，夹爪 0…100），
内部线性映射到标定时记录的编码器行程。SO101 官方标定约定
**标定零点 = 关节行程中点**，于是：

```
q_urdf[rad] = offset + sign × scale × 动作值
offset = (lower+upper)/2          ← URDF 行程中点
scale  = (upper-lower)/2 / 100    ← 每单位动作值对应的角度
```

实测动作值 ±100 对应 ±110°/±100°/±96.83°/±95°/±160°，与 URDF 限位逐一吻合，
说明这个仿射关系是对的。`tools/check_calib.py` 负责现场核对
（打印预测末端位置 + 逐关节 wiggle 观察方向）。

## 3. 逆运动学（重点）

### 3.1 解析解：两连杆（讲义公式）

正运动学：

```
x = L1·cosθ1 + L2·cos(θ1+θ2)
y = L1·sinθ1 + L2·sin(θ1+θ2)
```

逆解思路和讲义"两圆交点"完全等价：

```
r = √(x²+y²)
cosθ2 = (r² - L1² - L2²) / (2·L1·L2)      ← 余弦定理，θ2 = ±β
θ1 = atan2(y,x) - atan2(L2·sinθ2, L1 + L2·cosθ2)
```

* **多解**：`cosθ2` 反解出 ±β，对应"肘上 / 肘下"两组解；
* **无解**：`r > L1+L2`（太远）或 `r < |L1-L2|`（太近）。

代码里 `ik_planar_2r()` 返回两组解，测试把解回代正运动学，误差 1e-17。

### 3.2 数值解：为什么 SO101 不能直接用解析解

SO101 有 5 个自由度、连杆不在同一平面、还要求满足关节限位；
而且任务只是"位置"（3 维），自由度高（5），存在无穷多组解。
工程上直接用迭代：

```
重复：
    e  = p_target - p_current                     # 3 维位置误差
    J  = ∂p/∂q                                    # 3×5 位置雅可比
    Δq = Jᵀ(JJᵀ + λ²I)⁻¹ e                        # 阻尼最小二乘（DLS）
    Δq += (I - J⁺J)(q_rest - q)·k                 # 零空间正则
    Δq ← clamp(Δq, ±step_limit)                   # 限制单步幅度
    q  ← clip(q + Δq, 关节限位)
直到 |e| < 0.1 mm
```

三个细节各自解决一个问题：

**① 阻尼 λ —— 解决奇异位形**
手臂伸直时雅可比降秩，纯伪逆会算出无穷大的关节速度。
加上 `λ²I` 后解被"软化"。但固定 λ 会留下大约 `λ²` 量级的稳态残差
（实测 1.3 mm）。所以做成**自适应**（Levenberg–Marquardt 思路）：

* 新解让误差变小 → 接受，`λ ← 0.6λ`（趋向牛顿步，快速收敛）
* 新解让误差变大 → 拒绝，`λ ← 3λ`（趋向梯度下降，保证稳定）

实测：随机 300 个可达目标，成功率 **300/300**，最大残差 **0.099 mm**。

**② 零空间项 —— 解决冗余**
`N = I - J⁺J` 把任意向量投影到"不改变末端位置"的子空间。
把 `q_rest`（本次运动的起点）作为参考，多余的自由度就会被拉回原姿态，
表现为"走直线时腕部不乱翻、姿态基本不变"。

**③ 限位与步长 —— 解决可行性与平顺**
每次迭代都裁到 `[lower+margin, upper-margin]`；
单步不超过 `step_limit` 弧度，避免一帧跳太远。

### 3.3 无解 / 够不着怎么办

`move_tip_by()` 的策略：

1. 先按完整步长做 IK；
2. 失败就把步长**减半**再试，最多回溯 6 次（1/64）；
3. 找到第一个有解的步长 → 沿**原方向**走到那里；
4. 若连 1 mm 都走不动 → 打印 `IK 无解` 并原地不动。

这正好实现题目要求的"沿着有解的位置中、保留尽可能多的原运动方向的轨迹继续移动"。
`tools/kin_sanity.py` 里的实测轨迹：向上走 5 cm 能走两步整步，
之后步长依次减半（1/2、1/4、1/8…），最终停在可达边界。

## 4. 轨迹：怎么"在 1 秒内从 A 到 B"

三种速度曲线（`trajectory.py`）：

| 曲线 | 公式 | 特点 |
|------|------|------|
| linear | s = t | 匀速，起停瞬间速度突变，舵机会点头 |
| **minjerk** | s = 10t³-15t⁴+6t⁵ | 起停加速度连续，最平滑（默认） |
| trapezoid | 加速-匀速-减速 | 可指定最大速度，工程上最常见 |

预设动作 = `[(姿态A, 1.5s), (姿态B, 1.0s), ...]`，串成连续运动，
每一段的起点就是上一段的终点，所以不会出现停顿或跳变。

**限速模式**：只给速度上限时，耗时 = 最大关节行程 ÷ 速度上限，
夹爪用独立的开合速度，两者取较大者。

## 5. 伺服线程与安全

`ArmController` 内部跑一个 50 Hz 的后台线程：

1. 读回实测关节角（同时把指令状态与实测对齐——手动拖动机械臂后不会"跳"）；
2. 对当前运动采样插值，得到本周期该处的关节角；
3. 裁剪到 URDF 行程 ∩ lerobot 固有范围（±100）；
4. 下发。

设计上的几个取舍：

* **读写都在同一线程**：串口是独占资源，避免多线程抢占（lerobot 的 bus 不是线程安全的）；
* **启动时以实测姿态为初始目标**：避免上电瞬间机械臂猛冲；
* **异常记录不刷屏**：线程内异常保存下来，由主线程 `wait_until_settled()` 抛出；
* `hold()` 立即停止当前运动并保持位置。

## 6. 语音控制（2.1）

```
麦克风 ──sounddevice──> 16 kHz float32 ──VAD 切句──> faster-whisper ──> 文本
                                                                      │
                      ┌───────────────────────────────────────────────┤
                      v                                               v
             本地关键字规则（μs 级）                           LLM 兜底（可选，~1s）
             · 中文数字：两/十五/二十三
             · 单位：毫米/厘米/米/mm/cm/m
             · 方向词最长匹配（向左转 ≠ 左）
             · 意图优先级：停止 > 夹爪 > 移动 > 动作 > 姿态
                      └──────────────────┬────────────────────────────┘
                                         v
                                  执行（插值 / IK / 夹爪）
```

**端点检测（VAD）**：保留说话前 0.24 s 的环形缓冲（防止吞字），
RMS 超过 `energy_threshold` 判定开始，连续 1 s 低于阈值判定结束，
最长 8 s 兜底。这是最简单可靠的方案：不引入额外模型，延迟低。

**为什么 ASR 用 faster-whisper**：CTranslate2 推理后端 + int8 量化，
CPU 上 small 模型一句话 0.5~1.5 s，中文可用；完全离线，验收现场不受网络影响。

**为什么"规则优先、LLM 兜底"**：
规则零延迟、离线、可解释（能打印出匹配到哪个别名）；
LLM 泛化好但慢、要联网、可能编出不存在的姿态名。
两者结合的失败模式也清晰：转录错 → ASR 问题；转录对但解析错 → 补同义词。

## 7. 视觉闭环（2.2）

### 7.1 黑球检测

```
BGR → 灰度 → 高斯模糊 → 阈值反相(暗=前景) → 开运算(去噪) → 闭运算(补洞)
    → findContours → 三重筛选 → 选出"最圆最大"的那个
```

三重筛选：

1. **面积**：过滤噪点小斑和过大的背景；
2. **圆度** `4πA/P²`：圆≈1，直线/细长物低；
3. **填充率** `A/(π·r²_外接圆)`：圆≈1.0，正方形≈0.64。

第 3 条是这里的关键补充。只看圆度会误判：形态学的闭运算会把正方形的四个角
磨圆，实测黑色方块的圆度能到 0.91，光靠圆度（阈值 0.62）分不开；
而填充率对圆/方块分别是 0.98 / 0.64，加一条阈值 0.72 就干净了。

### 7.2 手眼映射与闭环

相机固定在末端，安装关系是常量，用一个仿射映射描述：

```
Δp_eef = gain_xy·du·image_right_axis          # 图像水平误差 -> 末端横向
       + gain_z ·dv·image_down_axis           # 图像垂直误差 -> 末端纵向
       + gain_depth·(1 - R/R_ref)·toward_ball_axis   # 半径比 -> 前后距离
```

`R_ref` 取第一帧的球半径，所以闭环会自动维持初始距离；
球变大（离得近）就后退，变小就前进，这也让"朝球运动"有了三维意义。

**闭环 = look-compute-move 循环**：
每走一小步（≤28 mm）就重新检测一次，因此：
* 手眼系数不精确没关系，反馈会纠正；
* 一帧没检测到球 → 原地等待，不乱走；
* 到工作空间边界 → 换方向或停下。

**自动纠错**：如果连续两步误差反而增大，说明该方向的符号装反了，
程序翻转 `signs` 并打印提示。这是对"相机装配方向未知"的工程兜底。

### 7.3 验证方式

`tools/test_vision_loop.py` 用一个**虚拟摄像头**（把球的世界坐标按针孔模型
投影成图像）喂给真正的闭环控制器，替代真实硬件来验证控制律：

* 初始误差 130 px → 7 步收敛到 15 px，末端 y 误差 8.0 cm → 0.9 cm、z 误差 5.7 cm → 0.7 cm；
* 把球换到另一侧（误差 202 px）→ 9 步收敛到 10.8 px，末端朝新方向移动。

这条测试证明了映射方向、增益、限幅、收敛性都是对的，
剩下的只是现场调阈值和增益。
